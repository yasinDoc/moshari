# Design: a2-exports

Task A2 in TASKS.md: `scripts/export_dispatch.py` writes sample dispatch notices for the
demo week into `exports/`, and the generated files are committed for the judges.

## Approach
Chosen: thin CLI over the existing `moshari.dispatch` templates, PDF printed by a headless
Chromium-family browser already on the machine (Edge on Windows, Chrome/Chromium elsewhere).
Why: the notice text and the HTML brief stay exactly what the app shows (one source of truth),
the PDF is the real brief printed, and requirements.txt gets no new dependency.
Rejected: reportlab PDF - a second layout that drifts from the HTML brief, plus a new dependency.
Rejected: Playwright - heavy dependency and a browser download for a few sample files.
Rejected: new notice wording or changes to dispatch.py/allocation.py/routing.py - A2 is an
exporter, not a template change; those modules are owned by others or already merged (PR 16).

## Components
- NEW `scripts/export_dispatch.py` (style of `scripts/train.py`: `sys.path` insert of `src/`,
  UTF-8 stdout reconfigure, argparse with the module docstring as help). Functions:
  - `build_rows(issue, horizon, stock, crews, select, policy) -> list[dict]`: ForecastService(
    load_dataset(), ForecastBundle.load()) -> forecast_all -> allocation.allocate(fc, svc.wards,
    stock, crews) -> routing.route_overflow(alloc, routing.load_bed_capacity()) ->
    dispatch.dispatch_table -> dispatch.select_rows(table, select). Same chain as
    ui/views/dispatch.py `build_table`.
  - `write_exports(rows, out_dir, settings) -> dict`: writes `sms/<ward>.txt`
    (`dispatch.sms(row) + "\n"`), `whatsapp/<ward>.txt` (`dispatch.whatsapp(row) + "\n"`),
    `briefs/<ward>.html` (`dispatch.brief_html(row)`), `briefs/all_briefs.html`
    (`dispatch.briefs_html(rows)`), and `README.md` (index). Same names and bytes as
    `dispatch.export_zip`. Files written with `newline="\n"`, UTF-8.
  - `find_browser(explicit=None) -> str | None`: `--browser` flag, then env `MOSHARI_BROWSER`,
    then known Edge/Chrome paths on Windows and macOS, then `shutil.which` of msedge, chrome,
    google-chrome, chromium, chromium-browser.
  - `print_pdf(browser, html_path, pdf_path)`: `<browser> --headless --disable-gpu
    --no-pdf-header-footer --print-to-pdf=<pdf> <file URI>`; adds `--no-sandbox` only on Linux
    when running as root; timeout 120 s; checks the result starts with `%PDF-`.
  - `main(argv=None) -> int`.
- CLI defaults = the app's defaults: `--issue` = `svc.default_issue_date()` (2025-06-02 for the
  bundled data), `--horizon 3`, `--stock 70` (percent), `--crews 40`, `--select high`
  (choices high|deficit|all), `--out exports`, `--pdf top` (choices top|all|none: `top` prints
  the highest-priority ward's brief and `all_briefs.pdf`), `--browser PATH`, `--require-pdf`.
- NEW `tests/test_export_dispatch.py`.
- NEW committed folder `exports/` (generated, never hand-edited).
- EDIT `README.md`: one short "Exports" section (how to run the script, what lands where).
- Untouched: everything under `src/`, `ui/`, `app.py`, `data/`, `models/`, `artifacts/`,
  existing tests, requirements files.

## Data flow
args -> build_rows (offline: bundled CSV + trained model, no network) -> rows sorted in the
table's priority order -> write_exports into a fresh temp dir next to `out` -> optional PDFs
printed from the temp dir's HTML -> the temp dir replaces `out/sms`, `out/whatsapp`,
`out/briefs` and `out/README.md` (old files in those three folders are removed, so a ward that
left the selection does not linger) -> print a summary: settings, ward count, files per folder,
PDF paths or the reason PDFs were skipped.
README.md inside exports lists: the exact command and settings, the target week, the ward list
with tier and deficit flag, and the file counts. No timestamps, so a rerun is byte-identical
(PDFs excepted: browsers stamp a creation date).

## Error handling
- `--issue` not among `svc.issue_dates` -> message naming the nearest valid dates, exit 2.
- `--horizon` not in the model's horizons, `--stock` outside 30-100, `--crews` < 0 -> exit 2.
- Selection empty -> message ("no ward is High or Critical for these settings"), exit 1, and
  `out` is left untouched.
- Any exception while writing -> temp dir deleted, `out` untouched, exit 1. No bare `except`.
- No browser found, or the browser fails or times out -> warning, text and HTML still written,
  exit 0; with `--require-pdf` -> exit 1 (and `out` untouched).
- Never calls the network; works with `MOSHARI_OFFLINE=1`.

## Tests -> criteria
- `.claude/goals/a2-exports-verify.py content` -> criterion 1 - catches: files hand-written or
  copied instead of generated by the script; wrong ward selection or settings; text that differs
  from `dispatch.sms/whatsapp/brief_html`; an SMS over 160 GSM-7 characters; missing
  all_briefs.html or README index; a stub or fake PDF (wrong header, too small, wrong page count);
  a non-deterministic rerun.
- `tests/test_export_dispatch.py` (>= 6 tests, all pass, none skipped) -> criterion 2 -
  catches: no layout test; no test that a rerun is identical; empty selection writes files or
  exits 0; a failed write leaves a half-written folder; stale ward files survive a rerun; missing
  browser crashes instead of skipping; invalid `--issue` exits 0. Tests use `--pdf none` or a
  fake browser executable, so they pass on machines without a browser.
- `{python} -m pytest -o addopts="" -q` -> criterion 3 (invariant) - full suite still passes.
- `.claude/goals/a2-exports-verify.py git` -> criterion 4 - catches: work left uncommitted;
  commits without the `version-onsite-final:` prefix; files changed outside SCOPE.
- Recheck guards: test counter >= 976 (no deleting tests); pins on `src/moshari/`, `ui/`,
  `app.py`, `tests/conftest.py`, `data/`, this design file and the verifier.

## Steps
1. Write `build_rows` + `write_exports` + `main` with `--pdf none` - fast check:
   `python scripts/export_dispatch.py --pdf none --out /tmp/x && ls /tmp/x/sms | wc -l` (26)
2. Add the temp-dir swap, validation and exit codes - fast check: `python scripts/export_dispatch.py --issue 1999-01-01; echo $?` (2)
3. Add `find_browser` + `print_pdf` - fast check: generate with `--pdf top` and run
   `head -c 5 exports/briefs/*.pdf`
4. Write `tests/test_export_dispatch.py` - fast check: `python -m pytest tests/test_export_dispatch.py -o addopts="" -q`
5. Generate the real `exports/` with `--pdf top`, add the README section - fast check:
   `python .claude/goals/a2-exports-verify.py content`
6. Commit with the `version-onsite-final:` prefix (no push), then run every proof.
